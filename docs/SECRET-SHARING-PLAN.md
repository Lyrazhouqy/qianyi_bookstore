# 跨书友机关：后续开发边界

2026-10-20。当前 v0.7.3 仅在同一浏览器保存创作与回应，不产生“其他人已发现”的反馈。清除浏览器数据会失去这些内容；固定手机试玩入口仍是 v0.6.23。

## 本轮结构

- `paperbook-secrets-v1`：`version`、按书 ID 分组的纸张。新创作只支持一张原色便笺及回应；保留旧版类型、纸色和正反面字段用于兼容已存内容。
- `paperbook-secret-drafts-v1`：按书保存未夹入的草稿。正式夹入失败时保留编辑内容并说明失败。
- 原阅读进度、接力信、玫瑰寻宝仍使用原存档。自创便笺的回应不混进《悉达多》预置接力信。

## P2 开发项及完成条件

1. 确定玩家身份与找回方式，建立 `secret` / `response` / `discovery` 数据。作者身份由服务端验证，书 ID 使用现有稳定 ID；草稿默认本机，只有主动发布才共享。
2. 明确发布、撤回、删除、可见范围和内容处理规则。已发布内容与未发布草稿必须能区分；不能直接把全部本机存档公开。
3. 实现按书读取及分页、限长/限频、响应幂等 ID、并发接力顺序；发布失败保留草稿，重试不会重复生成机关，离线不能假装发布成功。
4. 记录真实的首次发现与回应，去掉重复刷新/作者自己的阅读计数；反馈只由真实事件触发，不制造书友活动。
5. 用两台独立设备验收：甲在一本书中发布 → 乙未知内容地发现、阅读并回应 → 甲收到真实反馈；补充断网、重复提交、撤回、未授权修改与并发续写检查。

这份计划没有选择或开通外部服务，也没有部署多人服务器。P2实施前需要确定身份/可见范围及托管方案。

## 下一轮十分钟试玩

- 桌面与手机分开记录；首次玩家不预先告知《小王子》是目标。
- 比较翻开/取纸的误操作次数、归位到下一本可操作的等待、重复点击，以及创作后重访是否找到自己的纸。
- 分别记录情感参与、跨书探索和主动创作的发生顺序。先观察，再决定是否改变出现概率；本轮不调概率与玫瑰奖励内容。
