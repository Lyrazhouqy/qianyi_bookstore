0. 给 Codex 的执行指令
请直接在现有 qianyi_bookstore 工程里实现「短惊喜 → 自由探索 → 长参与 → 安静收尾」的可自然发生的整体节奏，而不是新做一个剧情演示、阅读摘要播放器、按钮模拟器或强制导览。先阅读仓库根目录 AGENTS.md、HANDOFF.md、README.md、docs/GAME-RHYTHM.md，运行现有测试并记录基线，检查现有工作树，建立安全的实验分支，分阶段提交。若仓库更新过，以当前运行代码为准，先做差异评估再改动。未经用户对体验验收，不要自动覆盖生产部署。

交付必须包含：可运行的游戏改动、自动化测试、5–10 分钟实际浏览器交互回放和事件记录、变更说明、风险清单。手机模拟不可以冒称实体 iPhone 验收。
1. 当前问题和设计目标
当前问题（不是要再次增加普通便笺）
1. 玩家行为过度集中于「选书 → 翻页 → 读一张读书心得 → 换书」；文字不同，操作与情绪变化不大。
2. 隐藏物件和接力信都具备潜力，但尚未在一次自然探索中形成不同长度、不同性质的体验节拍。
3. v0.13.0 取消冷却、额度和随机藏纸，修复了「真实书友留言看不到」的问题；不能为了造节奏退回人为隐藏内容。
4. 旧版玫瑰跨书寻宝可以保留，但不是本轮重点；不得把十分钟探索变成强制任务链。
核心体验假设
- 短惊喜：无任务地翻书，注意到与普通书页不一样的纸角/物件，亲自抽出，出现短促惊喜。
- 自由探索：惊喜后可以返回书店、阅读普通书、听音乐、漫游；没有马上下发下一个“目标”。
- 长参与：发现《悉达多》中的接力信后，逐折展开多位书友的文字，末尾自愿点击笔续写，形成比短惊喜更长的停留。
- 安静收尾：折信、归书后回到完整书店，无新任务弹窗、强制奖励或立即推下一机关；随时能离开或继续探索。
重要：这是体验结构，不是固定顺序脚本。 用户可能先打开《悉达多》，也可能十分钟都没遇到物件。禁止按 2/5/8 分钟强制刷新、解锁、弹提示。目标是能够自然出现这样的节奏，而不是保证每次都有全部四拍。

3. 本轮最小可玩范围（必须做）
S1：短惊喜——以《夜航西飞》为主要验证书
1. 玩家自由打开《夜航西飞》，正常看到简介与一般书页；不可在首页直接明示“这里有惊喜”。
2. 在书页中安排一个与普通文字便笺视觉不同的、原创且明确标注为演示内容的隐藏物件（例如旧明信片）。物件应有可感知的视觉信号：纸角、不同的厚度、露出的边沿等。采用现有折纸/夹页组件，不必重写整个阅读器。
3. 玩家主动点击/轻拖纸角，抽出 → 查看正面 → 翻到背面 → 放回。每一步有目的，不能变为「连续点下一条文字」。背面给出简短的理解转折，语言克制，不强推后续任务。
4. 第一次见到与再次访问都可以取出物件。不允许发现后物件消失，也不允许因为“本日次数已满”而无法找到。
5. 此事件不依赖“玩家必须先打开 N 本书”，不要求“到第 X 分钟”。当玩家主动打开这本书、翻到该夹页时即可见。
6. 《夜航西飞》原本已存在的真实留言、书页和回应必须继续可用，不能用这一个演示物件覆盖或替代。
7. 物件与普通便笺的呈现类型区分：物件需要观察与翻面；普通摘要只需轻量阅读。不要让书里的每张纸都触发同等长的仪式。
S2：自由探索——保留留白，不制造假奖励
1. 短惊喜结束后，玩家可立即合书/归位/点另一部书；不弹「下一目标」「恭喜」「继续寻找」之类提示。
2. 保留普通书《秘密花园》《海边的卡夫卡》等作为低强度探索内容；它们可以有完整的普通书友便笺，但不强制每次打开都出现高亮神秘机关。
3. 普通页面浏览应明显比抽取物件、逐折读信更轻。可以复用既有页角、翻页和短动画，减少不必要的重复开合书成本；不必把“刷刷刷”实验整个照搬进本轮。
4. 继续允许窗景、音乐、回看旧物件；保留已有内容，不在用户安静漫游时主动插入任务消息。
S3：长参与——保留《悉达多》接力信为独立高潮
1. 玩家主动打开《悉达多》，找到原有接力信，亲自抽出，沿折痕分段展开；原 A/B/C 三段结构和此前打磨过的动画逻辑保持。
2. 逐段新内容要随动作逐步出现，不能为了快读或随机刷页而一次性全部摊开。
3. 展开到末尾后，画面出现一支笔；只有点击笔才进入输入，不能自动弹键盘。
4. 允许不续写直接折好归位。若写下内容，按现有存档与回应体系保存，不覆盖旧内容；刷新/重进之后能再次找到。
5. 接力过程中禁用与其他翻页/换书的冲突操作，归位后恢复；检查快速点击、触屏拖动、文字选区和重复保存。
6. 接力信不是“下一个奖励”，玩家不应收到系统引导去打开《悉达多》。只有用户主动发现才开始。
S4：安静收尾——不自动再造高潮
1. 读完或续写接力信，折好并放回书架后，返回完整可交互的主场景，而不是结算屏。
2. 不展示经验值、连击、收集进度、任务链、必须再开一本书的提示。原有计数或个人手帐若存在，可以保持原位，不增加强调性弹窗。
3. 允许立即结束；如果继续漫游，普通内容正常可读、此前物件/接力信可复访。
4. 一次到访不要求一定在“接力后收尾”；已存在的玫瑰事件仍可独立自然发生，但避免这轮主动加强其曝光。
4. 内容编排原则
- 核心风格：克制、纸质、手工、细微；避免养成、签到、抽卡稀有度、任务清单。
- 书友真实心得是阅读内容，隐藏物件是游戏事件。 不要把所有心得包装成机关，更不能擅自改写真实书友原话来制造戏剧性。
- 新增原创演示物件必须有显式标记或数据源区分（例如 source: 'authored-playtest'）；不要冒用群友身份。尽量局限在 S1 的一个物件。
- “留白”指没有人工新高潮，不代表概率拦截书友已经留下的便笺。
- 玩家有权全部浏览同一本书的纸页、旧留言、新回应；随机只决定开场哪页，不决定内容是否存在。
- 旧玫瑰→《小王子》信封→邮票完整链路保留，不必在本轮改写文案或重新调密度。
5. 交互与状态要求
建议复用已有状态，新增事件标识但尽量不建立第二套冲突的「导演状态机」。若确需新增，采用可恢复的、低耦合的访次会话记录，与内容持久存档分开。
情况	期望行为
打开有隐藏物件的书	正常显示书，玩家可通过书页线索发现，非自动领取
抽出物件中返回/取消	不丢内容、不多记发现、不悬挂遮罩
看完物件后重新进书	可以复看，发现记录不累加错误
同书多张普通纸	全部可翻到，保存阅读位置/旧页规则不退化
打开接力信再退出	当前已展开部分按现有兼容规则恢复，不虚构新回应
点击笔开始输入后取消	不生成空白续写，草稿按已有规则保存
保存续写后刷新	无重复、无丢失、无匿名覆盖
触屏连续快速操作	不产生文字选区、重叠动画、双写或错误归位
接力信归位	返回自由漫游；不自动播放其他机关


除非确有需要，不要新增持久化字段；若新增，必须迁移旧 paperbook-v3、便笺、已读、草稿与发现状态，无破坏性清档。
6. 体验事件记录（仅本地测试，不上传私人阅读文字）
为使节奏可观察，增加一个开发/测试模式的轻量本地事件记录器（可以仅在 ?playtest=rhythm 或 Playwright fixture 开启）。正式模式默认不展示调试 UI、不上传数据。至少记录：
- session_start
- book_open / book_return（仅 bookId）
- page_turn（页码或翻页数量，非文字）
- artifact_cue_seen（仅当真正进入可见区域，不是内容初始化时）
- artifact_open / artifact_flip / artifact_return
- relay_open / relay_unfold / relay_pen_click / relay_save / relay_return
- session_end 或测试结束时导出
单事件含 elapsed_ms、book_id、event_type、detail（仅枚举/数量）；不采集信件正文、用户名、真实书友身份或任何秘钥。非必要不进入正式持久存储；可在开发模式复制 JSON 供分析。

分析角度：第一次物件发现前的行为、发现后是否自愿换书、接力信前后的停留/折数/是否续写、接力后是否仍被引导做任务、误操作和等待成本。不要把“播放了 600ms 动画”直接等同于玩家的感受。
7. 浏览器测试和试玩路径
自动化：必须覆盖 Chromium + WebKit
最低视口：320×小屏、390×844 手机；建议再测 1366×768 桌面。模拟触屏可使用现有 Playwright 基建，但不得称已完成实体手机验收。
1. 自由探索路径：打开《秘密花园》→ 若干普通页/便笺 → 归位 → 打开《夜航西飞》→ 找到物件 → 翻面 → 放回 → 返回书店。验证没有任务强制弹窗，原普通便笺仍可翻到。
2. 长参与路径：打开《悉达多》→ 取信 → 分段 A/B/C → 点笔 → 输入测试文字 → 保存 → 折信归位 → 刷新后验证回看、保存一次且无误覆盖。再测「不续写直接折返」。
3. 错序路径：用户先打开《悉达多》，完成后才去《夜航西飞》；机制正常，不要求顺序解锁。
4. 回访路径：已经看过明信片/接力信 → 关闭或刷新 → 重新打开；内容依旧可见，未读的其他书友便笺也可见。
5. 快速输入路径：抽出/翻面/折回时连续操作，翻书/收书/选下一本连点；无蓝色文字选区、没有堆叠遮罩、状态不死锁。
6. 旧存档与权限路径：保留 v0.13.0 旧数据、不重置发现额度字段、不损失 41+ 纸张，跨书页可见；防止演示数据冒充真实群友。
7. 旧玫瑰路径：线索前置满足后，干玫瑰→《小王子》信封→邮票仍能走通。
实际浏览器试玩：必须有，不只是自动点击
进行一轮 5–10 分钟开放式探索，不通过参数直接跳进结局，也不把书名或答案提前告诉试玩者。尽可能用 Cloud Browser/可交互浏览器执行；如不具备真实交互能力，明确报告限制并仅附模拟触控结果。

输出一张表：时间、玩家自己选择的书、观察/操作、发现/接力、停顿/重复动作、情绪判断（注明主观）。关注有没有自发的「短惊喜 → 漫游 → 长参与 → 余韵」，而不是为了满足剧本故意规定点击顺序。测试中如果玩家没有遇到全部四拍，照实记录，不补造成功。

9. 建议工作顺序与交付格式
1. 审查与基线：读 AGENTS.md 和 HANDOFF.md；核对当前分支及未提交工作；运行现有测试；提供预变更的范围清单。
2. 内容与数据：明确《夜航西飞》隐藏物件的演示数据来源与可复看策略；完全保留真实便笺；先做可见性和存档测试。
3. 交互改动：尽可能复用 siddhartha.js 的取出/展开/归位动画及 secrets.js 的页面编排，形成区别于读摘要的完整小物件交互；保持普通浏览轻量。
4. 接力与归位：确保接力逐折、笔触发、无强推下一环；处理快速操作和小屏状态。
5. 证据与验收：跑现有回归 + 新增 Playwright 测试；做一轮开放式体验；按失败优先级修正。
6. 提交与发布：先提供 commit/PR、差异、录像和测试结果；用户确认后，复用原 Vercel 项目正式发布，更新 HANDOFF.md、docs/GAME-RHYTHM.md 与发布清单。不要生成一堆孤立报告链接。
